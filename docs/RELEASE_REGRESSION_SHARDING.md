# Exact candidate regression strategy

The frozen Stable and Beta source refs each receive the same complete pytest collection on Windows and Ubuntu, divided deterministically into ten disjoint shards per OS. This produces 40 independent regression jobs, then four OS/channel desktop-preview jobs run only after every shard passes. The runner uses SHA-256 of pytest node IDs (not Python's randomized hash), so shard assignment is stable and reproducible without a third-party sharding plugin. Each shard records its exact source SHA, OS, Python/dependency manifest and JUnit report. A failed shard fails the aggregate workflow. Build-time package contract tests and actual portable/installed smoke remain in the parallel packaging workflow. This is test evidence, not legal, security or public-release approval.
