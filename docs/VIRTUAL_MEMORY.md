## Chapter 12 associative and virtual memory
Added functional 8×8 masked CAM (all valid matches, lowest-index priority) and one demand-paging model: 256 virtual words, 64 physical words using existing MemoryArray, 16-word pages, four frames, 2/4-entry exact associative TLB with LRU, FIFO/LRU page replacement, actual dirty-page writeback and reload, invalidation on eviction. Integrated bilingual nested CAM/virtual memory page in existing Logic Memory & bus inspector; actual page table, frame owners, TLB and trace, vector address path, demo. 37 learning routes. Tests authored: exhaustive four-bit masked comparison (4096 cases), four randomized paging oracle configurations, dirty eviction, invalid input, GUI routing. No real OS, memory protection, multiprocess, CPU integration or electrical timing. Both canvas head dac6bea workflows 45480455602/45480443205 verified green; newer exact-head CI and native visual review pending. No translator/release/installer changes.

CAM compares ((word XOR key) AND mask) == 0 for valid rows; mask 1 compares, 0 ignores. Page translation: VPN=VA//16, offset=VA%16, PA=frame*16+offset. Free frames first; FIFO selects oldest loaded, LRU selects least recently accessed. TLB uses exact four-bit VPN match and LRU, never contains an evicted mapping. Backing storage is a local in-memory educational array, not a real disk. On fault dirty victim is written before loading new page. No cycle costs modeled. Demo writes CAFE at VA 00, touches 01,10,20,30,40,00 (hex) and recovers CAFE. Reset clears all simulated storage.
