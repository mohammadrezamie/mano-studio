# Parallel full regression pilot — 2026-11-27

Owner directs faster releases without reducing coverage. GitHub standard public runners are free/unlimited in minutes, but concurrency is finite (Free standard runners 20; job matrix max 256). Official references: https://docs.github.com/en/actions/reference/limits and https://docs.github.com/en/actions/reference/runners/github-hosted-runners.

Pilot on a child of Beta packaging, without cancelling the existing full Windows/Ubuntu suite or touching the current release candidates. Four shards per OS (eight regression jobs). Each collects the complete unfiltered test suite with the existing platform/dependency/font setup, then partitions exact node IDs deterministically by SHA-256 sorted round robin. Preserve within-shard collection order, JUnit, environment, and one actual screenshot capture per OS. No pytest-xdist dependency or skipped test family. A separate gate requires all eight jobs green, exact source/platform/environment and identical collection per OS, complete non-overlapping membership, and a terminal result for every selected node. Setup skips remain visible; existing policy for skips is unchanged. Negative contract tests exercise missing, duplicate, failed and mismatched reports.

The pilot adds tests itself, so compare non-pilot node IDs against the serial baseline; do not equate count balance with duration balance. Inspect elapsed and queue times, any collection or isolation failures, visual output and coverage artifacts before replacing the serial gate. If a test relies on cross-test state, fix that test or group the dependency explicitly; do not omit it. Keep native installer, security and license checks independent. Eventually apply both tracks with a concurrency budget (4 x 2 x 2 = 16, leaving room for packaging and aggregate jobs). No claim of speedup or CI success until measured. Do not publish before acceptance.
