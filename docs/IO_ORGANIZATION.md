# Chapter 11 I/O organization


## Chapter 11 asynchronous handshake and priority interrupt
Independent ideal event-driven source/destination-initiated four-phase handshakes, explicit VALID/READY and 8-bit stable data bus, exactly one capture per transaction, invalid transitions reject before mutation. Four-device priority interrupt controller (IRQ0 highest), latched requests, enable mask, global IEN, higher-priority nesting, acknowledge clears selected request, EOI pops service stack. Parallel eligible bits and equivalent daisy grant path PI/ACK/PO; vector addresses 0100+4*i chosen for demonstration, not Basic Computer vectors or commercial PIC. Integrated bilingual I/O organization inspector with actual event history and priority state. Authored all 256 bytes in both handshake modes, all 256 pending/mask combinations, nested/masked/invalid cases and GUI regressions. Reference Mano 3rd ed. sections 11-3 and 11-5; university lecture https://old.dauniv.ac.in/public/frontassets/coursematerial/computer-architecture/CompArchCh11L04AsynchDataTransfers.pdf . No fixed asynchronous event duration, electrical timing, CPU ISR execution, DMA or serial framing yet. Chapter 8 postfix exact-head CI green; newer runs pending at inspection. Native visual review pending. Next DMA and FIFO/serial. No translator, installer or release changes.

Handshake controls expose only the valid next event; changing mode resets the transaction. Source initiation asserts VALID then READY (capture), releases VALID then READY. Destination initiation asserts READY, then VALID, releases READY (capture), then VALID. Requests coalesce while pending. The IRQ table shows a conceptual grant chain over eligible requests, not a second physical interrupt controller. Global IEN is manually controlled; service priority excludes equal/lower requests. No integration with chapter 5 CPU.
