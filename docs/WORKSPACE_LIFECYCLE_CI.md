# Qt workspace lifecycle benchmark

Source inspection: test_workspace.py closes a Workspace after each test, but closeEvent accepts the event and saves settings; it does not request widget deletion. Closed Qt objects can remain alive when Python or Qt references persist. App-wide stylesheet/font changes and motion-policy widget traversal may therefore grow expensive as tests accumulate. This is a hypothesis, not a diagnosed production leak.

The pilot calls normal close handling, then explicitly schedules destruction and flushes deferred-delete events; verifies the root, child and active timer become invalid. Restored Workspace is explicitly disposed and the temporary MotionTabs is parented to the fixture. No production code, test assertions, dependency or release gate changed. Benchmark compares identical selected cases on exact parent and child, fresh processes, same runner/Qt environment, and validates all outcomes and identities. Separate destruction test. Report durations; single-run ordering effects remain possible. Current serial and sharded runs are untouched. Only promote after actual native-platform results and full regression. If no meaningful benefit, do not promote.
